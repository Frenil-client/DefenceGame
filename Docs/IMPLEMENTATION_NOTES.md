# SYNTHESIS 구현 상세

[프로젝트 소개로 돌아가기](../README.md)

2026년 9월 기준 구현의 판단 근거와 검증 범위입니다. 수치는 개발 중인 CSV의 임시값이며, 최종 밸런스를 의미하지 않습니다.

## 1. 전투 반복 속도와 계산 검증을 함께 유지한 책임 분리

초기에는 전투, 유닛 이동과 투사체를 모두 Core의 결정적 틱 시뮬레이션에 넣었습니다. 전투 감각을 조정하는 과정에서 시뮬레이션 계약도 함께 바꿔야 했으므로, 전투 진행과 유닛 이동을 Unity 실시간 처리로 옮겼습니다.

그 결과 전투 계산이 헤드리스 테스트 밖에 놓였습니다. 스킬 나열 순서에 따른 피해 차이, 프레임 시간 반올림에 따른 장판 피해 차이, 파싱되지만 실행되지 않는 스킬 조합이 검증의 사각지대였습니다.

현재는 순수 계산을 Core에 두고, 그 계산에 필요한 시간과 난수 및 좌표는 Unity에서 공급합니다.

| Core의 순수 계산 | Unity의 실행 책임 |
|---|---|
| 트리거 판정과 효과 수집 | 프레임 시간, 난수 값과 좌표 공급 |
| 추가 공격 및 광역 대상 선택 | 쿨다운, 추격 이동과 투사체 표시 |
| 오라 범위와 스킬 ID별 중첩 판정 | 몬스터 수명과 처치 통지 |
| 방어력, 피해 배수와 시간 누산 | 계산 결과를 실제 전투 상태에 적용 |

확률 스킬은 굴린 난수를 인자로 받아 테스트에서도 같은 계산 경로를 실행합니다. Unity 전투 전체의 결정성은 보장하지 않으며, 동일한 입력을 받은 순수 계산의 결과를 검증합니다.

### Core의 결정성 규칙

| 항목 | 규칙 |
|---|---|
| 난수 | 시드를 주입한 DeterministicRandom 사용 |
| 시간 | 초당 20틱, 1틱 50ms의 정수 틱 |
| 수치 | long 기반 고정소수점, 스케일 1000 |
| 순회 | 결과에 순서가 영향을 주면 List 또는 정렬한 키 사용 |

Core 소유의 맵과 시뮬레이션은 같은 입력 조건으로 재현성을 확인합니다. 전투 처치처럼 Unity에서 들어오는 외부 입력이 달라지면 이후 Core 상태도 달라질 수 있습니다. 전체 런 리플레이와 서버 결과 검증은 구현 성과에 포함하지 않습니다.

## 2. 데이터로 조립하는 스킬과 중첩 규칙

[skills.csv](../Data/skills.csv)에 트리거와 효과를 정의하고, [units.csv](../Data/units.csv)에서 유닛에 배정합니다. 42종 유닛과 32종 스킬을 사용하며, 조합식 36개는 [recipes.csv](../Data/recipes.csv)가 원본입니다.

- 트리거: 상시, 평타 N회마다, 평타 시 확률
- 효과: 다중타격, 광역, 관통, 추가 피해, 치명타, 장판, 감속, 아군 버프, 방어력 감소
- 스킬 수: 유닛 등급 - 1. 1성은 0개, 5성은 4개

지원하는 조합에는 제약이 있습니다. 아군 버프처럼 오라 경로로 실행하는 효과는 상시 트리거만 허용합니다. 지원하지 않는 조합은 공통 검증기가 판정하며, 린터에서 오류로 처리합니다.

### 추가 피해와 치명타

강타 HEAVY3와 치명타 CRIT2가 같은 공격에서 발동하는 예입니다.

| 상황 | 피해 배수 | 기본 공격력 160일 때 |
|---|---:|---:|
| 미발동 | 100% | 160 |
| 강타만 발동 | 300% | 480 |
| 강타와 치명타 발동 | 600% | 960 |

추가 피해를 더한 뒤 치명타 배율을 곱합니다. `(100% + 200%) x 200% = 600%`이며, 데이터에서 두 스킬을 재배열해도 결과는 같습니다.

### 오라 중첩

범위 안의 같은 스킬 ID는 한 번 적용하고, 서로 다른 ID는 합산합니다.

| 범위 안 오라 구성 | 공격력 증가 |
|---|---:|
| 프리스트 1기, WARCRY1 | +15% |
| 프리스트 4기, 모두 WARCRY1 | +15% |
| 프리스트와 크루세이더, WARCRY1 + WARCRY2 | +40% |

동일 오라의 수치가 중복 증가하지 않는 규칙입니다. 유닛을 추가했을 때 생기는 개별 공격과 공간 커버리지까지 사라지는 것은 아닙니다. 장판도 범위와 스킬 ID로 중첩을 판정합니다.

방어력의 하한은 0, 감속 후 이동 속도의 하한은 기본 속도의 30%입니다. 전투와 UI는 같은 방어력 공식을 사용해 실제 피해와 표시 감소율이 일치하도록 합니다.

## 3. 조합과 전투 중 조작

조합 UI는 선택한 유닛이 대표 재료로 들어가는 조합식을 보여줍니다. 보유 재료로 가능한 조합은 초록색으로 강조하고, 합성 후에는 결과 유닛 기준으로 목록을 갱신해 연쇄 조합을 이어갑니다.

선택권은 특정 재료가 나오지 않아 조합이 막히는 상황에 플레이어가 개입하는 수단입니다. 석상과 보스 보상으로 얻어 상점에서 원하는 1성을 구매합니다.

![선택권을 소비해 원하는 1성 유닛을 구매하는 상점](images/shop-token.png)

개발 확인용 F9 상점은 선택권과 등급 제한 없이 상위 유닛을 꺼내 특정 스킬을 확인하는 통로이며 기본값은 꺼짐입니다.

입력은 눌렀다 놓은 거리로 선택과 명령을 구분합니다. 빈 곳으로 이동 명령을 내리면 경로와 점유 칸을 제외한 최근접 유효 칸으로 이동합니다. 몬스터나 석상을 지정하면 사거리까지 접근해 공격하고, 대상 사망 후에는 현재 위치 근처의 빈 칸에 정착합니다.

스폰 완료 후 웨이브 스킵을 누르면 잔여 몬스터를 다음 웨이브로 이월합니다. 결과 화면에서 재시작할 때는 런 세대 번호로 상태를 초기화하고, 열려 있던 팝업도 정리합니다.

## 4. 자체 UPM UI 패키지 적용

게임 내부에 있던 공통 UI 스택을 [unity-ui-system](https://github.com/Frenil-client/unity-ui-system)으로 분리하고 [manifest](../DefenceGame/Packages/manifest.json)에서 Git URL로 참조합니다.

| 게임이 소유 | 패키지가 소유 |
|---|---|
| GameScreen, 상점과 조합 및 결과 팝업 | 스택, 레이어와 정렬 순서 |
| 게임 데이터 바인딩과 버튼 동작 | 공유 모달 배경과 입력 차단 |
| 레이어 설정과 프리팹 표 | 부팅과 씬 수명 관리 |

문자열 ID로 팝업을 조회하던 호출을 `OpenAsync<ShopPopup>()`처럼 타입으로 바꿨습니다. 문자열 오타 가능성을 줄이지만, 프리팹 표 등록과 씬 구성의 정확성은 별도로 확인해야 합니다.

공유 모달 배경은 최상단 모달 아래로 이동하므로 팝업이 겹쳐도 배경이 누적해서 짙어지지 않습니다. UI별 루트 Canvas의 정렬 순서는 스택 기준으로 관리합니다.

범용 UI를 수정할 때 패키지 저장소에서 버전을 올리고 게임의 참조도 갱신해야 하는 비용이 생겼습니다. 게임 고유 코드와 공통 동작의 경계를 유지하기 위해 선택한 구조입니다.

## 5. 문자열 도구와 맵 저작 도구

[strings.csv](../Data/strings.csv)에 UI 문구와 스킬 설명을 두고, 치환 엔진은 Core에서 실행합니다. 설명에는 `{radius}` 같은 치환자를 사용해 번역 문장 안에서 숫자의 위치를 정할 수 있게 했습니다.

문자열 에디터는 키와 번역 문구로 검색하고, 선택 항목을 StringParser에 적용합니다. 등록하지 않은 키는 인스펙터에서 바로 표시합니다.

![등록되지 않은 키를 편집 시점에 표시하는 인스펙터](images/stringparser-error.png)

## 6. 자동 검증의 범위

[CI](../.github/workflows/ci.yml)는 main push와 main 대상 PR에서 [검증 스크립트](../Tools/ci.sh)를 실행합니다. 로컬 커밋 자체를 차단하는 훅은 이 파이프라인에 포함되지 않습니다.

1. Core의 UnityEngine using 참조 검사
2. .NET 빌드. UnityEngine의 완전수식 참조도 참조 어셈블리 부재로 차단
3. Core와 데이터 테스트
4. CSV 불변식 린터

확정 규칙인 Authoritative 위반은 오류 종료로 처리합니다. 임시 수치나 미정 모델에 걸린 Provisional 항목은 경고로 구분합니다.

자동 검증은 순수 계산과 데이터 규칙을 다룹니다. Unity 컴포넌트, 씬과 프리팹, 입력과 재시작 흐름, 실제 빌드는 별도 검증 대상입니다. 32종 스킬의 효과 발생 검사는 모든 전투 상황의 전수 검증을 뜻하지 않습니다.

밸런스 배치 시뮬레이션과 리포트 자동 판정, 실기 프레임률 측정은 후속 작업입니다. [Tools/Demo](../Tools/Demo)는 헤드리스 데모이며 완성된 밸런스 시뮬레이터로 제시하지 않습니다.
