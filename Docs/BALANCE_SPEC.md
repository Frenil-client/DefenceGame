## 0. 이 문서의 역할

이 문서는 데이터의 원본이 아니라 **데이터가 지켜야 할 규칙**을 정의한다. 실제 수치는 data/*.csv에 들어가고, 이 문서의 불변식은 tools/linter가 자동 검증한다.

여기 적힌 모든 수치는 **초기값이며 근거가 없다.** 시뮬레이터로 검증하기 전까지 어떤 숫자도 신뢰하지 않는다.

## 1. 축 정의

### 1-1. 속성 (5종)

| 속성 | 성격 | 상성 |
|---|---|---|
| 화염 | 지속 피해 부여 | 장갑에 약함 |
| 냉기 | 이동 속도 감소 | 비행에 강함 |
| 전격 | 연쇄 및 관통 | 다수에 강함 |
| 물리 | 안정적 단일 피해 | 상성 없음 |
| 신성 | 방어 감소 및 회복 | 보조 전용 |

### 1-2. 역할 (4종)

| 역할 | 성격 |
|---|---|
| 단일 | 단일 대상 고피해 |
| 광역 | 범위 피해, 개당 피해는 낮음 |
| 지속 | 시간당 피해, 방어 무시 |
| 보조 | 방깎, 슬로우, 저지 강화, 회복 |

관통(방어력 무시)은 역할이 아니라 속성 효과로 다룬다. 전격이 연쇄와 관통을, 신성이 방깎을 제공한다(1-1 참조). 이렇게 하면 유일 역할 흔함이 하나의 조합 경로만 갖는 구조 문제를 피한다.

### 1-3. 배치 (2종)

- **근접칸**: 경로에 인접. 저지 수를 가짐
- **원거리칸**: 경로에서 떨어짐. 저지 불가

## 8. 불변식 (린터 검증 규칙)

tools/linter가 data/*.csv를 읽어 자동 검증한다. 하나라도 위반하면 빌드를 막는다.

| ID | 규칙 |
|---|---|
| INV-01 | 모든 흔함 유닛은 최소 1개의 레어 레시피에 재료로 등장한다 (죽은 흔함 금지) |
| INV-02 | 모든 레어 유닛은 최소 1개의 유니크 또는 히든 레시피에 등장한다 |
| INV-03 | 모든 유니크 유닛은 최소 1개의 히든 레시피에 등장한다 |
| INV-04 | 어떤 속성도 전체 레시피 등장 횟수가 평균의 1.5배를 넘지 않는다 |
| INV-05 | 보스 1의 요구 조건을 만족하는 조합 경로가 2개 이상 존재한다 |
| INV-06 | 배치 코스트는 등급 상승에 따라 단조 증가한다 |
| INV-07 | 히든 유닛의 기대 DPS는 유니크의 1.6배 이상 2.2배 이하 |
| INV-08 | 모든 히든 레시피의 재료 총량 기준 도달 추정 웨이브가 12 이상 22 이하 |
| INV-09 | 근접칸과 원거리칸 배치 유닛 수의 비율이 등급별로 0.6에서 1.6 사이 |
| INV-10 | 보장 규칙 G1에서 G5는 뽑기 풀 구성으로 실현 가능하다 (반례 시드 없음) |

### 8-1. 개정 이력 (STEP 1)

STEP 1 에서 린터를 구현해 3장/4장 데이터에 돌린 결과, 불변식과 데이터 설계가 서로 어긋나는 지점이 드러나 아래를 개정한다. 근거는 데이터 로스터의 구조이며 감이 아니다.

- INV-01: '최소 2개' 에서 '최소 1개' 로 완화. 사유: C03 서리 정령(지속)과 C05 뇌전 궁수(관통)는 3장에서 각 역할의 유일 흔함이고 속성 짝도 하나뿐이라, 성립 조건(같은 속성 또는 같은 역할)을 만족하는 레어 레시피가 구조적으로 1개밖에 존재할 수 없다. '최소 2개' 는 로스터를 바꾸지 않는 한 충족 불가능하며, 4장이 의도한 C05/C09 희소성 장치와도 모순된다. '최소 1개' 는 죽은 흔함(어디에도 안 쓰이는 흔함)을 여전히 걸러낸다.
- INV-03: '정확히 1개' 에서 '최소 1개' 로 완화. 사유: 4-4장이 '재료 중복이 깊이를 만든다' 며 재료 재사용을 의도하는데 '정확히 1개' 와 정면 충돌한다. 또한 냉기 유니크가 U02 하나뿐이라 냉기 계열 히든 두 종(H02, H06)에 재료를 대려면 U02 중복이 불가피하다.

INV-02 는 규칙을 유지하고 데이터를 고쳤다. R10 수호사제가 어떤 상위 레시피에도 안 쓰이던 것은 규칙 문제가 아니라 4장의 누락이므로, H03 심판자의 재료를 R05 에서 R10 으로 교체해 편입했다 (R05 는 U04 에서 계속 쓰인다).

역할 축 개정 (관통 제거): 역할을 5종에서 4종으로 줄이고 관통을 전격 속성 효과로 옮겼다(1-2). 이유는 관통이 유일 역할(C05 한 종)이라 조합 경로가 하나로 막히고 R12(C05+C08)가 어떤 성립 조건도 만족하지 못하는 위법 조합이 되기 때문이다. C05 를 단일로 바꾸니 C05+C08 이 정당한 sameRole(단일) 페어가 되어 R12 문제가 자연 해소된다. INV-05 는 규칙 문구는 그대로 두되, 관통 경로를 역할이 아니라 C05 계보로 판정하도록 린터 구현을 조정했다. units.csv 의 C05/R03/R12/U03/H05 역할을 갱신했다.

## 9. 시뮬레이터 검증 항목

sim/은 Unity 의존성 없는 순수 C# 콘솔 프로젝트로 만든다. 전투가 완전히 결정적이므로 100% 재현 가능하다.

| ID | 질문 | 방법 | 성공 조건 |
|---|---|---|---|
| SIM-01 | 조합 트리 도달률 | 10만 런, 히든별 달성 비율 | 모든 히든이 10-25% 구간. H06만 5-12% 허용 |
| SIM-02 | 최악 시드 생존 | 하위 5% 시드로 1만 런 | 보스 1 격파율 80% 이상 |
| SIM-03 | 보조 역할군 확보 | 8웨이브 시점 관통 또는 방깎 보유율 | 100% (G2 보장 검증) |
| SIM-04 | 공세 가치 | 공세 런 vs 무공세 런 승률 | 둘 다 성립하되 공세 런이 5-15% 유리 |
| SIM-05 | 지배 조합 | 조합별 픽률과 승률 | 단일 조합의 승률 기여도 상위 15% 초과 없음 |
| SIM-06 | 보스 1 해법 균형 | 관통 경로 vs 방깎 경로 승률 | 두 경로 승률 차이 10%p 이내 |
| SIM-07 | 웨이브별 사망 지점 | 히스토그램 | 8, 16, 24에 피크. 중간 구간에 절벽 없음 |
| SIM-08 | 리더 균형 | 리더별 1만 런 | 승률 밴드가 서로 겹침 |

**SIM-01이 1순위다.** 히든 조합 도달률이 0%면 아무도 못 만드는 죽은 조합이고, 60%면 매번 나오는 뻔한 조합이다. 조합 디펜스의 생사가 여기서 갈린다.

## 10. 데이터 스키마

### units.csv

```
id, name, grade, element, role, placement, cost, hp, atk, atkSpeed, range, blockCount, redeployCd, isAdvance, note
```

- grade: common / rare / unique / hidden
- element: fire / ice / thunder / physical / holy
- role: single / splash / pierce / dot / support
- placement: melee / ranged
- isAdvance: 공세 파견 가능 여부 (bool)

### recipes.csv

```
resultId, mat1, mat2, conditionType, isHidden, unlockedByDefault
```

- conditionType: sameElement / sameRole / fixed

### waves.csv

```
waveIndex, enemySetId, spawnCount, spawnInterval, isBoss, bossId, difficultyScale
```

### bosses.csv

```
id, name, element, hp, armor, moveSpeed, isFlying, ignorePath, summonId, summonInterval, preDamageCapRatio
```

### relics.csv

```
id, name, ruleType, targetGrade, targetElement, param1, param2, rarity
```

## 11. 구현 순서

STEP 주석 기준 작성 순서를 명시한다.

```
STEP 1 (기반 도구)  CSV 임포터, ScriptableObject 생성, 린터 골격
STEP 2 (뼈대)      그리드, 경로, 적 이동, 코스트 회복, 배치와 회수
STEP 3 (핵심)      뽑기, 조합 판정, 등급 격자, 도감
STEP 4 (핵심)      보스 3기, 각성, 사전 타격 반영
STEP 5 (핵심)      공세 구역 해금, 파견, 이중 교전
STEP 6 (검증)      헤드리스 시뮬레이터, SIM-01부터 SIM-08까지
```

STEP 3이 완료된 시점, 즉 프리미티브 상태에서 뽑기와 조합만 돌아가는 단계에서 **"3판 연속 하고 싶은가"**를 판정한다. 아니면 그 뒤 전부가 무의미하다.

## 12. 확정되지 않은 것

이 초안에서 의도적으로 비워둔 항목이다. 시뮬레이터 없이 정하면 근거 없는 숫자가 된다.

- 유닛별 실제 hp, atk, atkSpeed, range 수치
- 웨이브별 적 구성과 스케일링 곡선
- 보스 HP와 방어력
- 유물 40-50종의 구체적 규칙
- 리더 4-6명의 패시브와 뽑기 풀 가중치

**순서는 이렇다.** 구조(이 문서)를 먼저 고정하고, 임시 수치를 넣어 시뮬레이터를 돌린 뒤, SIM-01부터 SIM-08까지를 통과할 때까지 수치만 조정한다. 구조를 고치는 것과 수치를 고치는 것을 섞지 않는다.
